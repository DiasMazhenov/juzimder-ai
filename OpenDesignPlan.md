# План улучшения AI-дизайна Juzimder по материалам Open Design

Дата: 28.10.2026. Статус: в работе; базовая оценка (Этап 0) завершена.

## Цель и границы

Повысить качество и разнообразие страниц, создаваемых по содержательным брифам без подсказок по вёрстке. Сохранить редактируемость в GrapesJS и Zero Block, существующий Project Data, серверную валидацию, CAS и пользовательские требования. Этот документ — отдельный план исследований и улучшений, а не утверждение о выполненных пунктах основного ROADMAP.

Источники: [Open Design](https://github.com/nexu-io/open-design), [профиль прототипа](https://github.com/nexu-io/open-design/blob/b7c5dd6d350bf54587a76bef1899bcbc183ea59d/plugins/_official/scenarios/od-next-strategy/assets/task-profiles/prototype.md), [структура дизайн-системы](https://github.com/nexu-io/open-design/blob/b7c5dd6d350bf54587a76bef1899bcbc183ea59d/specs/current/design-system-import-project.md), [сборка промтов](https://github.com/nexu-io/open-design/blob/b7c5dd6d350bf54587a76bef1899bcbc183ea59d/docs/prompt-composition.md). Последний источник описывает и расхождения между путями генерации; спецификация импорта дизайн-системы частично описывает целевое состояние.

## Принципы

- Бриф пользователя и выбранный им стиль важнее общих рекомендаций; не выдумывать факты, контакты и работающие действия.
- Пользовательские сайты и тема интерфейса конструктора имеют отдельные цвета и токены.
- Выбирать несколько уместных композиций, не навязывать единственный шаблон Hero. Учитывать действующее требование Hero не менее 75vh и проверять его на малых экранах.
- Уместные фотографии автоматически подбирать из открытых источников с сохранением автора, ссылки и условий лицензии; для Hero учитывать явно названный город и отклонять привязанные к другому месту объекты, а при отсутствии точного фото допускать нейтральный кадр; иконки страницы — из одной библиотеки в одном стиле.
- Правила фото, радиусов, выравнивания, бейджей и подписей сохраняются согласно пользовательским указаниям; качество не подтверждается только успешной проверкой JSON.
- Не переносить инструкции Open Design, запрещающие визуальный просмотр после генерации: пользователь просит скриншоты и исправления.
- Изолировать инструкции Skills от системных правил и не выполнять их команды; сохранять сервер как источник истины.

Точный текст утверждения UI не показывает; preview не создан, визуальная оценка NOT RUN, аудит не ослаблялся. Скриншот отказа сохранён в той же папке. Оба прогона оставлены без Apply/Save/Publish; Project Data остался на rev. 380. UI показывает ответы резервного профиля, но не причину отказа основного, поэтому контролируемый failover не подтверждён. Open Design этапы остаются открытыми.

Проверка локального runtime после release: PHP-служба на фиксированном порту 8080 раздавала прежний игнорируемый frontend bundle `00.00.314`, хотя исходники уже были на `00.00.315`. Выполнен штатный `npm run build` в `public`; после перезагрузки существующей вкладки редактор показывает `00.00.315` и `Ревизия 380 · Сохранено на сервере`. Ни Project Data, ни публикация сайта не изменялись. Коммиты исходников: `3250381`, `b023bbc`; визуальные ограничения и незакрытые этапы Open Design остаются без изменений.

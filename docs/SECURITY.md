# Безопасность первого среза

Статус: локальная foundation, не проверенный публичный SaaS. Все запросы к проекту проверяют session и owner. IDs случайные, но это не замена authorization. PDO prepared statements, CSRF header + SameSite Strict/HttpOnly cookies, session rotation после входа, password_hash/password_verify, лимит попыток auth 15/15 минут по REMOTE_ADDR. DB и backend вне public. Ошибки не возвращают SQL, credentials или stack traces. Логи содержат только класс исключения.

`npm run serve` явно включает локальный dev login `admin/admin`, ограниченный проверкой `REMOTE_ADDR` на loopback (`127.0.0.1` или `::1`). Он создаёт обычную пользовательскую запись без повышенной роли. Не задавать `JUZIMDER_DEV_AUTH=1` на публичном сервере; production-команды запуска не должны включать этот флаг.

Модель документа валидируется до записи: schemaVersion, pages/frames, структура components, типы/теги, запрет scripts и event attributes, ограниченные URI, rich text и CSS. JSON parser и readback сохраняют различие между объектами и массивами; malformed структура и policy violations получают 422 до SQL-записи. Проверка CSS нормализует escapes и comments до поиска `url()`, `@import`, `expression()` и опасных схем. Политика нарочно ограничивает MVP: произвольные embed/forms/scripts/custom plugins/CSS url() пока не поддерживаются. JSON Schema описывает структуру, PHP validator применяет security policy. Ajv тестирует JSON Schema v1 на эталонном GrapesJS документе и corpus malformed fixtures; PHP отдельно проверяет security-only случаи. Это не универсальный HTML sanitizer. Негативные случаи находятся в `tests/fixtures/invalid-documents.json`. До публичного запуска всё ещё нужны независимый sanitizer/parser review, fuzz/mutation tests, ограничения asset fetch и threat model для editor origin.

Preview запускается в iframe sandbox без allow-scripts/allow-same-origin. allowScripts=false в Core. CSP административной страницы: self scripts, inline styles для editor, HTTPS images, object-src none/base-uri none/frame-ancestors none. Не используем пользовательский HTML как серверный PHP. Upload endpoint отсутствует: изображения добавляются по HTTPS URL. Удалённые изображения раскрывают IP посетителя image host; proxy/cache и managed assets ещё не реализованы.

CAS version защищает от silent overwrite; save и restore вместе с revision INSERT/retention атомарны. Ввод с неизвестным типом или ошибкой не сохраняется. При 409 текущий редактор остаётся открыт, доступен export JSON и явная загрузка серверной версии; merge и force overwrite отсутствуют. Восстановление старой ревизии само создаёт новую версию и не удаляет историю. На проект остаются последние 200 ревизий; очистка старых записей выполняется в той же транзакции, что и сохранение.

`POST /api/projects/{id}/operations` использует session, owner check, CSRF и expected-version CAS. Операции ограничивают поля компонентов/стилей, блокируют циклическое перемещение, повторно проверяют весь Project Data и записывают результат стандартным `Store::save` в новую revision. `delete_component` требует `confirm: true`, но это только параметр API, не свидетельство пользовательского согласия. До подключения AI/UI клиент должен показать preview и получить явное подтверждение потенциально разрушительного изменения; endpoint сейчас не вызывается AI.

До публичного deployment: HTTPS, явная session idle/absolute expiry, email verification/recovery, account lifecycle, distributed rate limiting/quotas, резервное копирование с restore drill, dependency/SBOM и license review, доступ к var только PHP user, проверка reverse-proxy HTTPS detection. Сейчас TLS берётся из $_SERVER['HTTPS']; forwarded headers не доверяются. SQLite — один сервер с локальным диском; масштабирование не заявлено. Нельзя размещать repo root как document root. .env не загружается автоматически.

Модель угроз: браузер/AI/MCP — недоверенные клиенты. AI Engine хранит API key OpenRouter зашифрованным в отдельной таблице SQLite; случайный ключ шифрования приложения находится в sidecar-файле `.ai-key` с правами 0600 и не входит в Project Data, revisions, ответы API или логи. Эти два файла — единица backup. Полный захват файлового аккаунта приложения может раскрыть оба файла, поэтому каталог данных должен быть вне web root и закрыт от других пользователей ОС; deployment остаётся локальной foundation, не публично принятой SaaS-конфигурацией. Запись/чтение credentials требует session, project ownership и CSRF на изменениях; модель валидируется, ключ нельзя прочитать из UI, для удаления предусмотрена отдельная операция. AI design-plan endpoint ограничивает prompt 4000 символами, output — 1200 токенами и 1 МБ ответа, делает не более пяти вызовов в минуту на сессию и не мутирует Project Data. Только текст явно отправленного prompt уходит в OpenRouter. Это не production per-user quota и не денежный лимит. Публикация требует отдельного origin: user output не должен исполняться на origin админки.

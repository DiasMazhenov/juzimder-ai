# Безопасность первого среза

Статус: локальная foundation, не проверенный публичный SaaS. Все запросы к проекту проверяют session и owner. IDs случайные, но это не замена authorization. PDO prepared statements, CSRF header + SameSite Strict/HttpOnly cookies, session rotation после входа, password_hash/password_verify, лимит попыток auth 15/15 минут по REMOTE_ADDR. Имя локальной session cookie разделено по каноническому пути SQLite; если session owner отсутствует в текущей базе, сессия сбрасывается и UI предлагает войти заново вместо ответа 500. DB и backend вне public. Ошибки не возвращают SQL, credentials или stack traces. Логи содержат только класс исключения.

`npm run serve` показывает канонический адрес `juzimder-ai.localhost:8080`, но привязывает приложение только к loopback `127.0.0.1:8080` и явно включает локальный dev login `admin/admin`, ограниченный проверкой `REMOTE_ADDR` на loopback (`127.0.0.1` или `::1`). Он создаёт обычную пользовательскую запись без повышенной роли. Не задавать `JUZIMDER_DEV_AUTH=1` на публичном сервере; production-команды запуска не должны включать этот флаг.

Модель документа валидируется до записи: schemaVersion, pages/frames, структура components, типы/теги, запрет scripts и event attributes, ограниченные URI (включая только scoped project media refs), rich text и CSS. JSON parser и readback сохраняют различие между объектами и массивами; malformed структура и policy violations получают 422 до SQL-записи. Проверка CSS нормализует escapes и comments до поиска `url()`, `@import`, `expression()` и опасных схем. Политика нарочно ограничивает MVP: произвольные embed/forms/scripts/custom plugins/CSS url() пока не поддерживаются. JSON Schema описывает структуру, PHP validator применяет security policy. Ajv тестирует JSON Schema v1 на эталонном GrapesJS документе и corpus malformed fixtures; PHP отдельно проверяет security-only случаи. Это не универсальный HTML sanitizer. Негативные случаи находятся в `tests/fixtures/invalid-documents.json`. До публичного запуска всё ещё нужны независимый sanitizer/parser review, fuzz/mutation tests, ограничения asset fetch и threat model для editor origin.

Preview запускается в iframe sandbox без allow-scripts/allow-same-origin. allowScripts=false в Core. CSP административной страницы: self scripts, inline styles для editor, self/HTTPS/data images, object-src none/base-uri none/frame-ancestors none. Upload принимает только PNG/JPEG/GIF/WebP, проверяет сигнатуру и MIME, ограничивает файл 4 МБ, стороны 8192 px, 40 Мп, проект — 20 МБ и 200 файлов. SVG и произвольные data URLs запрещены; имена безопасно отображаются, байты остаются в SQLite вне document root. Media GET требует owner session. Публичный router обслуживает media только если она присутствует в активном snapshot; публикация не читает произвольные файлы по клиентскому пути.

Формы: SMTP-параметры принадлежат проекту и читаются/изменяются только владельцем; пароль зашифрован. SMTP test endpoint разрешает не более 3 попыток за 10 минут на project/owner; счётчик атомарный и фиксируется до DNS/TCP, поэтому ошибки политики и соединения тоже учитываются. Перед SMTP-соединением транспорт разрешает A/AAAA один раз, проверяет каждый ответ и подключается к проверенному IP, сохраняя исходный hostname для TLS-проверки. По умолчанию блокируются loopback, private, link-local, reserved, shared, documentation, benchmark и translation ranges; разрешены только глобальные адреса на портах 25, 465, 587 и 2525. Для self-hosted внутреннего relay администратор может перечислить точные адреса в `JUZIMDER_SMTP_EGRESS_ALLOWED_IPS`. `JUZIMDER_SMTP_EGRESS_ALLOWED_PORTS` задаёт точный список разрешённых портов и заменяет стандартный набор; CIDR-разрешения не принимаются. Эти переменные — deployment policy, не секреты; `.env` автоматически не загружается. Системный firewall публичного хоста всё равно должен ограничивать исходящие подключения, это отдельная production мера. Rate limit опубликованных отправок формы остаётся отдельным механизмом.

Static ZIP export и публикация доступны только после session и project-owner check. Renderer повторно применяет Document policy, выводит только разрешённые теги/атрибуты, экранирует текст/SEO, фильтрует CSS properties/selectors/media queries и не переносит scripts. Publish требует CSRF и expected-version CAS; backend активирует immutable snapshot из сохранённого Project Data и только используемых проверенных файлов. Public host распознаётся строгим project-id subdomain, не запускает admin session и отдаёт только главную, безопасные slug routes, общий CSS и allowlisted изображения активного snapshot под restrictive CSP. Unpublish убирает активный pointer, но сохраняет историю snapshots. Production требует отдельной wildcard DNS/TLS конфигурации.

CAS version защищает от silent overwrite; save и restore вместе с revision INSERT/retention атомарны. Ввод с неизвестным типом или ошибкой не сохраняется. При 409 текущий редактор остаётся открыт, доступен export JSON и явная загрузка серверной версии; merge и force overwrite отсутствуют. Восстановление старой ревизии само создаёт новую версию и не удаляет историю. На проект остаются последние 200 ревизий; очистка старых записей выполняется в той же транзакции, что и сохранение.

`POST /api/projects/{id}/operations` использует session, owner check, CSRF и expected-version CAS. Операции ограничивают поля компонентов/стилей, блокируют циклическое перемещение, повторно проверяют весь Project Data и записывают результат стандартным `Store::save` в новую revision. `delete_component` требует `confirm: true`, но это только параметр API, не свидетельство пользовательского согласия. До подключения AI/UI клиент должен показать preview и получить явное подтверждение потенциально разрушительного изменения; endpoint сейчас не вызывается AI.

До публичного deployment: HTTPS, явная session idle/absolute expiry, email verification/recovery, account lifecycle, distributed rate limiting/quotas, резервное копирование с restore drill, dependency/SBOM и license review, доступ к var только PHP user, проверка reverse-proxy HTTPS detection. Сейчас TLS берётся из $_SERVER['HTTPS']; forwarded headers не доверяются. SQLite — один сервер с локальным диском; масштабирование не заявлено. Нельзя размещать repo root как document root. .env не загружается автоматически.

Модель угроз: браузер/AI/MCP — недоверенные клиенты. AI Engine хранит API key OpenRouter зашифрованным в отдельной таблице SQLite; случайный ключ шифрования приложения находится в sidecar-файле `.ai-key` с правами 0600 и не входит в Project Data, revisions, ответы API или логи. Эти два файла — единица backup. Полный захват файлового аккаунта приложения может раскрыть оба файла, поэтому каталог данных должен быть вне web root и закрыт от других пользователей ОС; deployment остаётся локальной foundation, не публично принятой SaaS-конфигурацией. Запись/чтение credentials требует session, project ownership и CSRF на изменениях; модель валидируется, ключ нельзя прочитать из UI, для удаления предусмотрена отдельная операция. Только явно отправленный текст prompt уходит в OpenRouter; API принимает только это поле, ограничивает его 4000 символами и делает не более пяти вызовов в минуту на сессию. Это не production per-user quota и не денежный лимит.

Полностраничная генерация не принимает модельный Project Data или произвольные операции. Сервер проверяет структурированный JSON, разрешённые HTML-теги/атрибуты и классы, от 3 до 9 секций, один hero, уникальные namespaced IDs и разрешённые ссылки; CSS ограничен списком свойств/значений, классами из этой разметки, 120 правилами и двумя уровнями max-width media rules. JavaScript, event handlers, SVG, forms, iframe, внешние ресурсы и CSS url() отклоняются. Preview использует opaque sandbox без allow-scripts/allow-same-origin и CSP, запрещающую сеть, изображения и шрифты. Импорт происходит только после отдельного подтверждения в GrapesJS Core; Project Data сохраняется прежним owner/CSRF/CAS/version validator. Сгенерированное HTML/CSS не исполняется на origin админки. Это ограниченный product sanitizer и не является универсальной защитой против всех browser/parser различий; независимый sanitizer review и fuzz/mutation tests остаются перед публичным deployment.


## Zero Block v1

ZeroData — bounded typed data, не HTML/JS. Строгие поля, 300 элементов, 8 уровней групп, 256 KiB, конечные диапазоны, safe marked text, allowlisted styles/URLs. Renderer экранирует строки; SVG/HTML embeds/скрипты не поддержаны. Приватные изображения (включая responsive src) проверяются прежним Store asset ownership gate. Scoped save требует owner/auth/CSRF/version и использует Store::save/revisions. Изменения соседей не подменяются. Родительская CSP не ослаблялась; Zero HTML/CSS не требует исполнения scripts. BroadcastChannel payload не является разрешением на запись; dirty main/409 сохраняют локальную работу. Подробности: ZERO_BLOCK.md.

# Архитектура

Браузер → same-origin PHP JSON API → Store → PDO SQLite. Vite собирает frontend в public; backend/ и var/ находятся вне document root. GrapesJS загружается динамически при открытии редактора. Нет Studio SDK, Node runtime сервера, микросервисов и форков Core.

- src/main.js: auth/dashboard/editor lifecycle, Pages/Devices/UndoManager/StyleManager/Traits/Layers, native components, debounced autosave, history and conflict recovery.
- src/blocks.js: структурные definitions Hero/Features/CTA/Text/Image. Не HTML templates.
- backend/Domain.php: Document policy и Store с проверкой owner, CAS-save/restore и revisions (последние 200 на проект).
- backend/api.php: session/CSRF/input/errors и маршрутизация.
- backend/migrations/: sequential SQLite schema upgrades; schema v4 adds immutable `publication_versions` and an active `project_publications` pointer; schema v6 adds project-owned raster image BLOB storage.
- public/router.php: dispatches the admin app/API and isolates `<project-id>.<JUZIMDER_PUBLIC_HOST_SUFFIX>` to static public routes.

Проект одновременно выполняет роль workspace/site; внутри несколько Pages. `project_assets` хранит проверенные растровые файлы как BLOB в приватной SQLite; Project Data ссылается на них стабильным owner-scoped URL. Публикация использует `publication_versions` для immutable snapshots и `project_publications` для активного снимка; public router отдаёт только медиа, включённые в активный snapshot.

API: GET session, POST register/login/logout, GET/POST projects, GET/PUT projects/{id}, GET projects/{id}/assets, POST projects/{id}/assets и GET projects/{id}/assets/{assetId}/file, GET projects/{id}/revisions (UI показывает до 50 последних), POST projects/{id}/revisions/restore, GET/PUT/DELETE projects/{id}/ai/settings, POST projects/{id}/ai/design-plan и POST projects/{id}/ai/generate-page, POST projects/{id}/operations и GET projects/{id}/export/static, GET projects/{id}/publication, POST projects/{id}/publish и POST projects/{id}/unpublish. Проектные операции требуют session.user и owner check; mutations требуют X-CSRF-Token. `ProjectOperations` сохраняет typed operations через `Store::save` с expected-version CAS, Document validation и revision insert. `ai/generate-page` принимает только user prompt и не меняет документ; сервер валидирует и namespace-ит модельный HTML/CSS до отдачи в sandbox preview. После отдельного подтверждения GrapesJS Core импортирует HTML в editable component models и CSS в project style rules, затем обычный save использует полный Project Data envelope/CAS/revision pipeline. Static export повторно валидирует сохранённый envelope и выдаёт ZIP только владельцу, копируя только используемые растровые изображения; `StaticSiteExporter` преобразует allowlisted компоненты в HTML, ограничивает CSS правила/медиазапросы, применяет SEO/design tokens и не экспортирует скрипты. Publish повторно рендерит только сохранённый документ, проверяет project owner и expected document version и атомарно активирует новый immutable snapshot; unpublish удаляет активный указатель, оставляя версии в истории. OpenRouter credentials принадлежат проекту: API key хранится зашифрованным в `project_ai_profiles`, шифровальный key-файл с правами 0600 лежит рядом с SQLite. UI и Project Data получают только статус/модель, секрет возвращается только внутреннему backend-коду для вызова фиксированного OpenRouter endpoint.

Текущий `ProjectOperations` — начальный pure application service для преобразований дерева. Его набор ещё неполный: duplicate отложен до remap ссылок и styles. AI, editor и MCP пока не вызывают этот service. Следующий общий слой должен дать всем transport одинаковые owner, policy, expected-version и revision правила. MCP будет отдельным transport-процессом, работающим с backend без открытого браузера; endpoint сейчас не существует.

Обычное сохранение не меняет опубликованный сайт. Preview редактора остаётся sandbox iframe; для media preview встраивает авторизованные растровые байты как data URLs. JSON export — переносимый документ с проектными ссылками на изображения. Явный publish рендерит static HTML/CSS и сохраняет используемые изображения в base64-виде внутри immutable snapshot; public router не запускает admin session и отдаёт только главную, page slugs, общий CSS и опубликованные media paths.

GrapesJS API сверены с официальными docs: https://grapesjs.com/docs/modules/Storage.html и https://grapesjs.com/docs/api/editor.html , Context7 /grapesjs/grapesjs и исходники установленной 0.23.8. Для сохранения используется полный Project Data, а не getHtml/getCss. HTML/CSS показываются в sandbox preview; при подтверждённом AI-импорте Core преобразует проверенный HTML/CSS в editable component models и project style rules, которые сохраняются в том же Project Data envelope.


## Absolute Zero Block · 00.00.098

Zero Block расширяет Core компонентом и одним каноническим zeroData; отдельная страница Zero Editor использует обычный session/API. backend/ZeroBlock.php отвечает за policy/scoped replacement; ZeroBlockRenderer.php — static HTML/CSS. Сохранение проходит через прежний Store::save/CAS/revisions, а экспорт/публикация — через StaticSiteExporter. JS-модули src/zero разделяют модель, affine transforms, group operations, renderer, Inspector и editor lifecycle. BroadcastChannel только уведомляет; сохранённый серверный документ остаётся authority. Контракт, формулы и границы приёмки — ZERO_BLOCK.md.

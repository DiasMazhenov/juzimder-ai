Статус: принято для первого вертикального среза, 20.10.2026. Основание: PHP_GRAPESJS_AUDIT.md, commit источника 4a464cc3edf54db3ddacdad4b3ddab5bcf7b8589. Вариант C.

## Почему PHP, не Next.js или Laravel сейчас

Первый срез — ограниченный CRUD, auth и сохранение JSON. PHP без runtime Node соответствует hosting preference, SQLite не требует отдельного DB server. Vite выполняет только сборку; DOM редактором управляет GrapesJS, поэтому React/Tailwind не добавлены. Laravel полезен при росте auth/очередей/миграций; его отсутствие сейчас сокращает установку, но потребует пересмотра до публичного SaaS. Next.js не даёт нужного преимущества этому вертикальному срезу и усложняет PHP deployment. Это выбор для foundation, не утверждение о превосходстве native PHP для всей платформы.

## Модель и последствия

Единственная модель документа — envelope schemaVersion=1 + engine=grapesjs + полный getProjectData. Не создаём второй component tree с lossy adapter. Компоненты — нативные GrapesJS component definitions; pages/frames/styles/assets остаются внутри data. AI и MCP позже обязаны использовать ту же модель и сервис сохранения с version precondition, а не прямую запись SQL или HTML.

SQLite с локальным диском и одним PHP-инстансом; PostgreSQL/MySQL миграция до горизонтального масштабирования. Полный документ сохраняется транзакционно и создаёт ревизию; HTTP 409 при stale version. Undo/Redo ограничены открытой editor session. Без autosave в этом срезе: явное сохранение и beforeunload warning.

Исходники CMS не копируются. Лицензия собственного продукта пока не выбрана владельцем: не назначаем её самовольно. THIRD_PARTY_NOTICES сохраняет обязательные уведомления библиотек. Публичный релиз под open-source лицензией требует отдельного выбора владельца и dependency review; это не блокирует локальную реализацию.

# AI Engine

## Профили OpenRouter · версия 00.00.020

Владелец проекта может создать несколько OpenRouter профилей с собственными именами, API-ключами и ID основной модели. Владелец может настроить необязательную резервную модель в том же профиле. В списке можно выбрать активный профиль, изменить его или удалить. AI-планирование использует активный профиль; при удалении активного автоматически выбирается другой сохранённый профиль, а при удалении последнего AI отключается. При редактировании пустое поле ключа сохраняет прежний ключ, пустое поле резервной модели отключает fallback.

После одной повторной попытки основной модели на временной сетевой ошибке, HTTP 408/429 или 5xx сервер отправляет тот же структурированный запрос через указанную резервную модель с тем же API-ключом. Ошибки авторизации и валидации не переключают модель. Каждый вызов может тарифицироваться отдельно по правилам OpenRouter; интерфейс показывает обе модели и предупреждает о возможной дополнительной стоимости. Резервная модель хранится в `project_ai_profiles.fallback_model`; миграция v6→v7 оставляет её пустой для существующих профилей.

API-ключ вводится в парольное поле и шифруется сервером через libsodium secretbox. Браузер получает только ID профиля, название, модели и признак активного профиля; значения ключей никогда не возвращаются. Секреты хранятся отдельно от Project Data, общих настроек и ревизий и не выводятся в application logs. Миграция schema 4 переносит прежний ключ в профиль «Основной профиль», сохраняя шифротекст, модель и optimistic version.

Шифровальный ключ приложения создаётся рядом с SQLite как файл <путь к базе>.ai-key с правами 0600; каталог базы и sidecar должны находиться вне public/ и быть доступны только PHP service user. Для восстановления AI-профилей нужны SQLite и этот файл. Если sidecar утрачен, приложение не создаёт новый ключ шифрования поверх прежних данных: владелец должен ввести API-ключи заново. Ключи OpenRouter не читаются из окружения и не включаются в резервный JSON проекта.

GET /api/projects/{id}/ai/settings возвращает список профилей и безопасный статус активного. Создание, редактирование, выбор активного и удаление доступны через POST /api/projects/{id}/ai/profiles, PUT/DELETE /api/projects/{id}/ai/profiles/{profileId} и POST /api/projects/{id}/ai/profiles/{profileId}/activate. Все изменения требуют авторизации владельца проекта, CSRF и ожидаемой версии общего списка профилей. Старые PUT/DELETE /ai/settings остаются совместимыми с прежним single-profile UI. Endpoint плана POST /api/projects/{id}/ai/design-plan использует только текущий активный профиль.

## Собственный текст в готовых секциях · версия 00.00.021

Design-plan возвращает обычные текстовые значения для фиксированных текстовых полей девяти встроенных секций. Каждый ответ привязан к section ID и к заранее заданному порядку полей локального preset; сервер проверяет наличие ровно одного набора на каждую выбранную секцию, точное число строк, длину до 220 символов и отсутствие HTML/разметки, управляющих символов и URL. Браузер повторяет валидацию и вставляет только `content` в известные text/link компоненты. Никакие AI-HTML, CSS, атрибуты, компоненты или операции напрямую не принимаются.

До подтверждения UI показывает весь сгенерированный текст рядом с планом. После подтверждения его можно редактировать обычными средствами GrapesJS; типизированные операции проходят owner/CSRF/version и Project Data validation и записываются одной обычной ревизией. Максимум ответа OpenRouter для расширенного плана ограничен 3200 токенами. Никакого дополнительного live-вызова при реализации версии 00.00.021 не выполнялось; успешная проверка настоящего провайдера остаётся отдельным пунктом приёмки.

## AI-планирование · версия 00.00.006

В редакторе есть форма design-plan, которая сначала проверяет настройки AI текущего проекта. Если ключ не настроен, кнопка отправки prompt остаётся выключенной, а редактор предлагает открыть «Настройки сайта → AI Engine». Перед запросом UI сообщает, что на OpenRouter уйдёт только текстовое описание и что содержимое страницы/Project Data не передаётся. До нажатия «Составить план» описание не отправляется.

Проверенный ответ отображается в preview: тип сайта, аудитория, цель, стиль, восемь цветов, список секций, заметки по адаптивности и доступные model/usage/cost metadata. Frontend повторно ограничивает план фиксированными section IDs и hex colors. Применение требует отдельного подтверждения и создаёт только `create_component` операции из локальных библиотечных presets. Никакой AI HTML/CSS/JSON напрямую не сохраняется. Серверный `/operations` повторно проверяет owner, CSRF, expected version, allowlists и весь Project Data, затем создаёт одну обычную revision.

Секции добавляются в конец выбранной страницы, текущий контент сохраняется. Цвета из AI-плана применяются только к новым секциям; типографика и radius наследуются от текущей темы проекта. Глобальные design tokens и существующие блоки не меняются.

## Параметры запросов и границы

Ответ запрашивается через OpenRouter Chat Completions с `response_format.type=json_schema`, строгой схемой, `provider.require_parameters=true` и `usage.include=true`. Сервер повторно проверяет результат. Один запрос к модели ограничен 3200 выходными токенами, 25 секундами и 1 МБ ответа; на одну PHP-сессию допускается до пяти вызовов за минуту. Это защита от случайного повтора, а не денежная квота. Основная модель повторяется один раз после временной ошибки или HTTP 408/429/5xx; после неудачи сервер вызывает настроенную резервную модель максимум один раз с теми же ограничениями. Ошибки авторизации и валидации не повторяются через fallback.

В версии 00.00.020 из редактора отправлен только синтетический prompt с профилем `openrouter/free`; интерфейс ответил «AI-провайдер временно недоступен», предпросмотр не появился. Мы не применяли план, не сохраняли страницу и не публиковали её. Успешная live-проверка и save/reload после ответа всё ещё не приняты. Получение списка моделей, production per-user quota, денежный лимит и мониторинг расходов ещё не реализованы. Внешние запросы требуют HTTPS на deployment и явного действия пользователя в AI-панели.

# AI Engine

## Конфигурация OpenRouter · версия 00.00.010

API-ключ и ID модели задаются владельцем проекта в «Настройки сайта → AI Engine». Ключ вводится в парольное поле, шифруется сервером через libsodium `secretbox` и хранится отдельно от Project Data, общих настроек и ревизий. Браузер получает только признак настроенного провайдера, модель и версию конфигурации; ранее сохранённый ключ нельзя прочитать из интерфейса. Пустое поле при сохранённом ключе оставляет его без изменений. Кнопка удаления отключает AI для этого проекта.

Шифровальный ключ приложения автоматически создаётся рядом с SQLite как `<имя-базы>.ai-key` с правами `0600`; файл находится вне `public/` при соблюдении настройки deployment. Для восстановления AI-конфигурации нужны и SQLite, и этот файл. Если файл утрачен, приложение не генерирует новый ключ поверх зашифрованных данных: владелец должен ввести API-ключ заново. Ключи OpenRouter не читаются из окружения, не включаются в резервный JSON проекта и не выводятся в application logs.

API настроек: `GET/PUT/DELETE /api/projects/{id}/ai/settings`. Чтение и запись требуют авторизации владельца проекта; изменения требуют CSRF, строгой проверки model/key и ожидаемой версии конфигурации. Секреты не входят в проектные ревизии. Endpoint плана: `POST /api/projects/{id}/ai/design-plan`; он использует ключ и модель выбранного проекта.

## AI-планирование · версия 00.00.006

В редакторе есть форма design-plan, которая сначала проверяет настройки AI текущего проекта. Если ключ не настроен, кнопка отправки prompt остаётся выключенной, а редактор предлагает открыть «Настройки сайта → AI Engine». Перед запросом UI сообщает, что на OpenRouter уйдёт только текстовое описание и что содержимое страницы/Project Data не передаётся. До нажатия «Составить план» описание не отправляется.

Проверенный ответ отображается в preview: тип сайта, аудитория, цель, стиль, восемь цветов, список секций, заметки по адаптивности и доступные model/usage/cost metadata. Frontend повторно ограничивает план фиксированными section IDs и hex colors. Применение требует отдельного подтверждения и создаёт только `create_component` операции из локальных библиотечных presets. Никакой AI HTML/CSS/JSON напрямую не сохраняется. Серверный `/operations` повторно проверяет owner, CSRF, expected version, allowlists и весь Project Data, затем создаёт одну обычную revision.

Секции добавляются в конец выбранной страницы, текущий контент сохраняется. Цвета из AI-плана применяются только к новым секциям; типографика и radius наследуются от текущей темы проекта. Глобальные design tokens и существующие блоки не меняются.

## Параметры запросов и границы

Ответ запрашивается через OpenRouter Chat Completions с `response_format.type=json_schema`, строгой схемой, `provider.require_parameters=true` и `usage.include=true`. Сервер повторно проверяет результат. Один запрос ограничен 1200 выходными токенами, 25 секундами и 1 МБ ответа; на одну PHP-сессию допускается до пяти вызовов за минуту. Это защита от случайного повтора, а не денежная квота. Сервер повторяет один явный transient HTTP-ответ из ограниченного набора; сетевые сбои, ошибки авторизации и невалидный результат не повторяются.

Реальный вызов OpenRouter и save/reload после реального ответа остаются отдельной live-проверкой; сохранение конфигурации с тестовым ключом не доказывает её доступность у провайдера. Получение списка моделей, production per-user quota, денежный лимит и мониторинг расходов ещё не реализованы. Внешние запросы требуют HTTPS на deployment и явного действия пользователя в AI-панели.

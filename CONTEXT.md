# Juzimder AI — контекст проекта

Обновлено 22.10.2026. Цель: самостоятельная платформа визуального создания адаптивных сайтов с AI и будущим MCP. Основной репозиторий: https://github.com/DiasMazhenov/juzimder-ai . Репозиторий ведётся в main; ветка отслеживает origin/main. Текущая версия продукта: 00.00.035 (npm SemVer 0.1.35). Постоянный локальный адрес: http://juzimder-ai.localhost:8080/ (`npm run serve`, loopback only); старые loopback-ссылки перенаправляются на него.

Версия 00.00.012 добавляет per-page SEO metadata в settings schema v4: заголовок, описание, robots и HTTPS social image сохраняются в ревизиях после server validation. В .012 приложение ещё не обслуживало публичные страницы.

Версия 00.00.013 добавила owner-authenticated static ZIP export всех сохранённых страниц. Версия 00.00.014 добавила owner-authenticated публикацию сохранённого Project Data как неизменяемых HTML/CSS snapshots на отдельном per-project origin, повторную публикацию с новой версией и снятие с публикации с сохранением истории. Версия 00.00.015 добавила owner-authenticated preview последней сохранённой ревизии всех страниц в sandboxed iframe; preview не меняет Project Data, историю ревизий и активную публикацию. Версия 00.00.016 переносит навигацию настроек в боковую панель проекта; на мобильной ширине она становится горизонтальной прокручиваемой панелью. Публичный router не открывает сессию или editor API и отдаёт только allowlisted статические пути. По умолчанию локальный suffix — `juzimder-ai.localhost:8080`; production deployment требует wildcard DNS/TLS и отдельной настройки suffix. Версия 00.00.017 добавляет несколько зашифрованных OpenRouter профилей на проект: название, ключ и модель редактируются отдельно; владелец выбирает активный профиль, а удаление активного переключает на другой сохранённый. Старый ключ мигрирует в профиль «Основной профиль». AI-профили не входят в Project Data и ревизии; значения ключей не возвращаются браузеру. Версия 00.00.018 добавляет приватную библиотеку PNG/JPEG/GIF/WebP: владелец загружает до 4 МБ на файл (20 МБ и 200 файлов на проект), вставляет изображение в редактор, а сервер проверяет MIME, сигнатуру, размеры и принадлежность ссылки проекту. В Project Data сохраняется scoped URL; Preview встраивает private bytes как data URL, ZIP содержит используемые файлы, публикация копирует их в immutable snapshot.

## Принятые решения

- Phase 0: статический аудит PHP-GrapesJS commit 4a464cc3edf54db3ddacdad4b3ddab5bcf7b8589. Подробности в docs/PHP_GRAPESJS_AUDIT.md. Fork отклонён из-за persistence/auth/DB/deployment/licensing проблем.
- Вариант C: собственный PHP 8.2+ API, PDO SQLite, browser JS/CSS, Vite build. PHP hosting без Node runtime. GrapesJS Core 0.23.8, без Studio SDK/форка.
- Каноническая модель: schemaVersion=1, engine=grapesjs, data=getProjectData. Сохраняем pages/frames/components/styles/assets/metadata, не отдельное HTML дерево. Структурная схема в schemas/, authoritative policy в Document validator.
- Project объединяет workspace/site для первого среза. Owner проверяется сервером. Mutations: session + CSRF + validation + expected version.
- Локальные PHP-сессии отдельных SQLite-баз используют разные cookie names; если cookie содержит owner, которого нет в текущей базе, сервер безопасно сбрасывает сессию и просит войти заново.
- Лицензия собственного продукта ожидает выбора владельца. Исходники PHP-GrapesJS не переносились. Notices Core сохранены.

## Реализовано

Auth регистрация/вход/выход, password hashing/session rotation/CSRF/rate limit. Локальная команда `npm run serve` включает dev login `admin/admin` только для loopback соединений; это тестовая учётная запись без отдельной admin-роли и режим запрещён для публичного хостинга. Dashboard: список и создание проектов. Несколько страниц в одном документе. Editor: библиотека структурных секций, слои, traits и style inspector, Flex/Grid, responsive devices, Undo/Redo, текст, managed raster library и HTTPS изображения, preview sandbox, JSON export. На ширине до 800 px панели холста, секций и свойств переключаются отдельными кнопками; есть Cmd/Ctrl+Z, Shift+Z/Y и Cmd/Ctrl+S с защитой полей ввода. Сервер хранит полный document и до 200 транзакционных revisions. Schema v1 уточнена и согласована с runtime policy; malformed/security JSON fixtures проверяются до сохранения. Автосохранение с debounce 1,4 с; CAS 409 при параллельной записи предлагает экспорт или загрузку серверного состояния. История последних 50 ревизий в UI; восстановление пишет старое состояние в новую ревизию и не стирает текущую историю. Выход из редактора сначала пытается сохранить изменения. AI-панель генерирует полноценную страницу HTML/CSS по одному введённому описанию, показывает её в sandbox preview, а после отдельного подтверждения импортирует обычные редактируемые GrapesJS components и CSS rules с сохранением в новой CAS-ревизии. Сервер ограничивает HTML/CSS allowlist-правилами; JavaScript и внешние ресурсы не допускаются. OpenRouter не получает Project Data.

Инспектор размеров даёт режимы ширины Авто/Hug/Fill и высоты Hug/Fill; четыре min/max поля принимают CSS-размеры с px, %, rem, em, vw или vh. Пустое значение снимает ограничение. Эти стили сохраняются в каноническом Project Data.

Рабочая структура: src/, backend/Domain.php, backend/api.php, backend/migrations/, public/router.php, schemas/, tests/, docs/. Не создавать пустые пакеты для будущих функций. Production сборка public/index.html + assets игнорируется Git и воспроизводится npm ci && npm run build. var/app.sqlite — локальные данные, не Git.

## Ограничения / риски

Не готовый SaaS: нет email verification/recovery, срока бездействия session, production deployment, backup restore drill. SQLite schema v7 с переносом прежних AI credentials в profiles, таблицей raster assets и optional fallback model применяется последовательными migrations при bootstrap; общий migration runner с backup/rollback orchestration ещё не реализован. SQLite для одного сервера, нагрузка не измерена. Core lazy chunk около 1.10 МБ raw / 291 КБ gzip; Vite предупреждает о размере. Свободный пользовательский JS/embed/CSS url запрещены. Панельный мобильный workflow проверен в браузерном viewport 390×844 и 768×1024. Дополнительная частичная responsive matrix: 9/10 секций на mobile 375 px и tablet 768 px, FAQ также на desktop; полная mobile/responsive матрица Image, touch на реальном устройстве, clipboard и keyboard/a11y ещё не приняты.

AI UI для design-plan, preview/confirmation и typed preset operations реализованы в 00.00.006; генерация структурированного текста для полей встроенных секций — в 00.00.021; ограниченная полностраничная HTML/CSS генерация, sandbox preview и импорт в editable GrapesJS components/style rules — в 00.00.023. Per-project encrypted OpenRouter profiles с редактированием/выбором реализованы в 00.00.017, резервная модель и retry policy добавлены в 00.00.020. Исправление local stale-session/project-create recovery — в 00.00.011. Static ZIP export реализован в 00.00.013; immutable publication versions и отдельный local/public origin — в 00.00.014; owner-authenticated preview сохранённого кандидата — в 00.00.015. Production wildcard DNS/TLS и custom domains ещё не реализованы. Address-scoped AI edits реализованы в 00.00.030; live AI acceptance остаётся открытой. MCP, Zero Block и advanced Auto Layout не реализованы; генератор не создаёт изображения, формы или JavaScript. В 00.00.022 live OpenRouter preview с восемью секциями появился, Project Data остался на ревизии 0. В 00.00.023 unit/API fixture проверки пройдены без live-вызова; подтверждение импорта, реальное сохранение/reload/restore/publish всё ещё нужно принять отдельно. Не называть весь MVP завершённым. Полный SBOM/CVE audit upstream не выполнен, audit статический, без exploit proof.

## Контракт image slots и диагностика output · версия продукта 00.00.028

JSON Schema и системная инструкция разрешают image slots только как пустые `div.ai-image-slot` с `data-image-slot` равным `hero` или `section-1`…`section-8`. Hero обязателен и располагается внутри hero section; сервер добавляет его, если модель пропустила marker. Допустимы максимум три уникальных дополнительных slot; `<img>`, URLs, filenames и image descriptions от модели не принимаются. Причины отклонения результата разделены на формат, HTML и CSS с короткими безопасными сообщениями; исходный ответ модели и содержимое страниц в сообщения не попадают. CSS schema включает пример синтаксиса, принимаемого sanitizer, и запрещает comments, fences, variables и вложенные selector rules; flat rules в простых media queries разрешены. Если модель нарушает схему, HTML или CSS allowlist, выполняется одна исправляющая попытка с исходным prompt и безопасной подсказкой без echo отвергнутого ответа; обе попытки остаются под тем же sanitizer, а tokens/cost суммируются. В интерфейсе это раскрыто до отправки запроса.

Три live-проверки на QA-странице с моделью Nemotron до согласования typed slot markers показали поочерёдно общий отказ, CSS rejection и HTML rejection. После согласования image-slot контракта live preview прошёл серверную проверку: 4 секции и 4 slots (hero + три секции), 897 входных и 2271 выходной токен, cost $0. Ревизия 6 не менялась; изображения не выбраны, импорт и сохранение не выполнялись.

## Автоматические требования Skill · 00.00.035

Markdown Skill может содержать один fenced блок `juzimder-rules` с JSON `{"schemaVersion":1,"requirements":[...]}`. Поддерживаются до 20 требований с уникальными id: heading_count (tag h1–h6, count 0–50), section_count (min/max 3–9), text_present/text_absent (text до 200 символов) и responsive_css (наличие max-width media rule). Неподдерживаемые поля/типы, malformed JSON и противоречащие требования отклоняются до сохранения. База и Project Data contract не меняются: правила версионированы внутри текста Skill.

Сервер проверяет очищенный HTML/CSS, возвращает ID, статус и измеренные evidence вместе с SHA-256 текста Skill. При провале — одна исправляющая попытка с ID нарушенных требований без отправки отвергнутого HTML; повторный провал не возвращает импортируемый дизайн. UI показывает автоматические результаты отдельно от ручного чек-листа. DOM textContent не доказывает видимость, а наличие media rule не доказывает качественную адаптацию. Разбор произвольного natural-language Skill в правила, rendered geometry/contrast и независимая визуальная оценка остаются открытыми.

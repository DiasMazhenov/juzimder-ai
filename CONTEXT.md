# Juzimder AI — контекст проекта

Обновлено 21.10.2026. Цель: самостоятельная платформа визуального создания адаптивных сайтов с AI и будущим MCP. Основной репозиторий: https://github.com/DiasMazhenov/juzimder-ai . Репозиторий ведётся в main; ветка отслеживает origin/main. Текущая версия продукта: 00.00.022 (npm SemVer 0.1.22). Постоянный локальный адрес: http://juzimder-ai.localhost:8080/ (`npm run serve`, loopback only); старые loopback-ссылки перенаправляются на него.

Версия 00.00.012 добавляет per-page SEO metadata в settings schema v4: заголовок, описание, robots и HTTPS social image сохраняются в ревизиях после server validation. В .012 приложение ещё не обслуживало публичные страницы.

Версия 00.00.013 добавила owner-authenticated static ZIP export всех сохранённых страниц. Версия 00.00.014 добавила owner-authenticated публикацию сохранённого Project Data как неизменяемых HTML/CSS snapshots на отдельном per-project origin, повторную публикацию с новой версией и снятие с публикации с сохранением истории. Версия 00.00.015 добавила owner-authenticated preview последней сохранённой ревизии всех страниц в sandboxed iframe; preview не меняет Project Data, историю ревизий и активную публикацию. Версия 00.00.016 переносит навигацию настроек в боковую панель проекта; на мобильной ширине она становится горизонтальной прокручиваемой панелью. Публичный router не открывает сессию или editor API и отдаёт только allowlisted статические пути. По умолчанию локальный suffix — `juzimder-ai.localhost:8080`; production deployment требует wildcard DNS/TLS и отдельной настройки suffix. Версия 00.00.017 добавляет несколько зашифрованных OpenRouter профилей на проект: название, ключ и модель редактируются отдельно; владелец выбирает активный профиль, а удаление активного переключает на другой сохранённый. Старый ключ мигрирует в профиль «Основной профиль». AI-профили не входят в Project Data и ревизии; значения ключей не возвращаются браузеру. Версия 00.00.018 добавляет приватную библиотеку PNG/JPEG/GIF/WebP: владелец загружает до 4 МБ на файл (20 МБ и 200 файлов на проект), вставляет изображение в редактор, а сервер проверяет MIME, сигнатуру, размеры и принадлежность ссылки проекту. В Project Data сохраняется scoped URL; Preview встраивает private bytes как data URL, ZIP содержит используемые файлы, публикация копирует их в immutable snapshot.

## Принятые решения

- Phase 0: статический аудит PHP-GrapesJS commit 4a464cc3edf54db3ddacdad4b3ddab5bcf7b8589. Подробности в docs/PHP_GRAPESJS_AUDIT.md. Fork отклонён из-за persistence/auth/DB/deployment/licensing проблем.
- Вариант C: собственный PHP 8.2+ API, PDO SQLite, browser JS/CSS, Vite build. PHP hosting без Node runtime. GrapesJS Core 0.23.8, без Studio SDK/форка.
- Каноническая модель: schemaVersion=1, engine=grapesjs, data=getProjectData. Сохраняем pages/frames/components/styles/assets/metadata, не отдельное HTML дерево. Структурная схема в schemas/, authoritative policy в Document validator.
- Project объединяет workspace/site для первого среза. Owner проверяется сервером. Mutations: session + CSRF + validation + expected version.
- Локальные PHP-сессии отдельных SQLite-баз используют разные cookie names; если cookie содержит owner, которого нет в текущей базе, сервер безопасно сбрасывает сессию и просит войти заново.
- Лицензия собственного продукта ожидает выбора владельца. Исходники PHP-GrapesJS не переносились. Notices Core сохранены.

## Реализовано

Auth регистрация/вход/выход, password hashing/session rotation/CSRF/rate limit. Локальная команда `npm run serve` включает dev login `admin/admin` только для loopback соединений; это тестовая учётная запись без отдельной admin-роли и режим запрещён для публичного хостинга. Dashboard: список и создание проектов. Несколько страниц в одном документе. Editor: библиотека структурных секций, слои, traits и style inspector, Flex/Grid, responsive devices, Undo/Redo, текст, managed raster library и HTTPS изображения, preview sandbox, JSON export. На ширине до 800 px панели холста, секций и свойств переключаются отдельными кнопками; есть Cmd/Ctrl+Z, Shift+Z/Y и Cmd/Ctrl+S с защитой полей ввода. Сервер хранит полный document и до 200 транзакционных revisions. Schema v1 уточнена и согласована с runtime policy; malformed/security JSON fixtures проверяются до сохранения. Автосохранение с debounce 1,4 с; CAS 409 при параллельной записи предлагает экспорт или загрузку серверного состояния. История последних 50 ревизий в UI; восстановление пишет старое состояние в новую ревизию и не стирает текущую историю. Выход из редактора сначала пытается сохранить изменения. AI-панель принимает описание только после явного нажатия, показывает проверенный план и палитру, а применение после отдельного подтверждения добавляет встроенные редактируемые секции typed operations одной CAS-ревизией. Описание уходит OpenRouter; Project Data не передаётся. Цвета плана применяются к новым секциям, текущие шрифт и радиус наследуются, а существующие секции и глобальная тема проекта сохраняются.

Инспектор размеров даёт режимы ширины Авто/Hug/Fill и высоты Hug/Fill; четыре min/max поля принимают CSS-размеры с px, %, rem, em, vw или vh. Пустое значение снимает ограничение. Эти стили сохраняются в каноническом Project Data.

Рабочая структура: src/, backend/Domain.php, backend/api.php, backend/migrations/, public/router.php, schemas/, tests/, docs/. Не создавать пустые пакеты для будущих функций. Production сборка public/index.html + assets игнорируется Git и воспроизводится npm ci && npm run build. var/app.sqlite — локальные данные, не Git.

## Ограничения / риски

Не готовый SaaS: нет email verification/recovery, срока бездействия session, production deployment, backup restore drill. SQLite schema v7 с переносом прежних AI credentials в profiles, таблицей raster assets и optional fallback model применяется последовательными migrations при bootstrap; общий migration runner с backup/rollback orchestration ещё не реализован. SQLite для одного сервера, нагрузка не измерена. Core lazy chunk около 1.10 МБ raw / 291 КБ gzip; Vite предупреждает о размере. Свободный пользовательский JS/embed/CSS url запрещены. Панельный мобильный workflow проверен в браузерном viewport 390×844 и 768×1024. Дополнительная частичная responsive matrix: 9/10 секций на mobile 375 px и tablet 768 px, FAQ также на desktop; полная mobile/responsive матрица Image, touch на реальном устройстве, clipboard и keyboard/a11y ещё не приняты.

AI UI для design-plan, preview/confirmation и typed preset operations реализованы в 00.00.006; генерация структурированного текста для всех полей поддерживаемых секций, server/client validation, preview и editable output — в 00.00.021. Per-project encrypted OpenRouter profiles with edit/select support реализованы в 00.00.017, прежняя конфигурация мигрирует в профиль «Основной профиль». Резервная модель профиля и её retry policy добавлены в 00.00.020. Исправление local stale-session/project-create recovery — в 00.00.011. Static ZIP export реализован в 00.00.013; immutable publication versions и отдельный local/public origin — в 00.00.014; owner-authenticated preview сохранённого кандидата — в 00.00.015. Production wildcard DNS/TLS и custom domains ещё не реализованы. Также не реализованы произвольные AI-компоненты, targeted AI edits, MCP, Zero Block и advanced Auto Layout. В 00.00.020 синтетический live prompt завершился временной недоступностью; в 00.00.022 проверена генерация настоящим OpenRouter-профилем: preview с восемью секциями появился, Project Data остался на ревизии 0. Подтверждение применения и save/reload/publish flow ещё не проверялись. Не называть весь MVP завершённым. Полный SBOM/CVE audit upstream не выполнен, audit статический, без exploit proof.

## Резервная модель OpenRouter · версия продукта 00.00.020

В AI Engine можно задать необязательную резервную модель для каждого профиля. При временном сбое транспорта или HTTP 408/429/5xx основная модель получает одну повторную попытку, после чего сервер отправляет тот же структурированный запрос резервной модели. Ошибки авторизации и локальной валидации fallback не запускают. SQLite migration v6→v7 добавляет `fallback_model`; старые профили остаются без fallback. В форме показано предупреждение, что дополнительный вызов может тарифицироваться отдельно.

`npm test`, `npm run build`, PHP syntax и `git diff --check` проходят. В открытом проекте `Design token QA` UI подтвердил активный профиль `openrouter/free`; отправлен только синтетический prompt. Редактор вернул «AI-провайдер временно недоступен». План не появился, кнопка применения не нажималась, страница не сохранялась и не публиковалась. Успешные live preview и `save/reload/restore` остаются непроверенными.

## Собственный текст AI-плана · версия продукта 00.00.021

Строгий OpenRouter plan включает текст по фиксированным полям каждой выбранной секции. Сервер и браузер проверяют section IDs, уникальность и полноту наборов, количество текстовых слотов, предел 220 символов и отсутствие HTML/URL/управляющих символов. JS подставляет значения только в известные `text`/`link` nodes локальных preset-компонентов; пользователь видит все строки до отдельного подтверждения. Применение сохраняет обычные GrapesJS компоненты через typed operations и текущий CAS/revision pipeline; Project Data envelope/schema и AI key storage не менялись. Completion cap — 3200 tokens.

## Исправление маршрутизации AI · версия продукта 00.00.022

Активная OpenRouter-модель публиковала поддержку `max_tokens`, а приложение с `provider.require_parameters=true` отправляло `max_completion_tokens`. Лимит ответа сохранён на 3200, но теперь передаётся в `max_tokens`, чтобы совместно маршрутизироваться через провайдера, объявляющего этот параметр. PHP завершал запрос на 30-секундном лимите во время retry, поэтому браузер видел `Failed to fetch`; для design-plan endpoint установлен 120-секундный бюджет, достаточный для retry и опциональной fallback-модели. Отдельно локальный PHP-сервер был остановлен; постоянный адрес поднят через `npm run serve`. В браузере активная модель успешно создала preview с восемью секциями; применение и изменение Project Data не выполнялись, ревизия осталась 0.

Полный `npm test`, `npm run build`, PHP syntax checks для всех PHP-файлов и `git diff --check` прошли. Изолированный API flow подтвердил дальнейшие edit/restore/preview/ZIP/publish этапы без OpenRouter.

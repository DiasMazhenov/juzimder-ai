# Juzimder AI

From idea to website. Платформа визуального создания сайтов на базе **GrapesJS Core**. Собственная оболочка редактора, PHP API и переносимое состояние проекта. Самостоятельный продукт, не официальный продукт GrapesJS.

**Версия продукта: 00.00.036 · Статус: foundation.** AI Engine поддерживает несколько редактируемых OpenRouter профилей с зашифрованными ключами и необязательной резервной моделью на временные сбои. AI-дизайн создаёт HTML/CSS-структуру из 3–9 редактируемых секций, показывает sandbox-предпросмотр и импортирует страницу только после подтверждения. Встроенный профиль Taste добавляет предметно-ориентированную идею, серверные структурные gates и обязательную ручную приёмку предпросмотра на desktop/tablet/mobile; рядом остаётся стандартный профиль. Backend ограничивает HTML/CSS allowlist-правилами; JavaScript и внешние ресурсы не принимаются. На OpenRouter передаются текстовое описание и выбранный профиль. Если ответ модели нарушит формат или проверки, выполняется одна исправляющая попытка; повторное нарушение завершает запрос без применения. Модель задаёт визуальные слоты только безопасными пустыми `div.ai-image-slot` маркерами; владелец выбирает изображения из приватной библиотеки проекта в интерфейсе. Байты, имена файлов и ссылки на изображения не отправляются провайдеру. После импорта выбранные файлы становятся обычными редактируемыми изображениями GrapesJS. API-ключ настраивается в «Настройки сайта → AI Engine». В библиотеке доступны PNG/JPEG/GIF/WebP до 4 МБ на файл, общий лимит — 20 МБ и 200 изображений на проект. ZIP экспортирует используемые изображения, публикация включает их в неизменяемый снимок. Также доступны страницы, глобальные стили, SEO и отдельный public origin; production DNS/TLS и custom domains пока не настроены. AI Engine также хранит до 10 Markdown Skills на проект с редактированием и активацией. Выбранный Skill и его чек-лист отправляются в OpenRouter только при генерации; перед импортом пользователь отмечает ручные проверки. Блок juzimder-rules добавляет серверные проверки заголовков, секций, текста и адаптивного CSS с одной исправляющей попыткой и отказом при повторном нарушении. Кнопка «Разобрать Skill с AI» предлагает правила и ручные проверки с цитатами из исходника; владелец проверяет полноту перед переносом черновика в форму. Остальные требования проверяются вручную; идеальное следование произвольным инструкциям не гарантируется. npm SemVer — 0.1.60, productVersion — 00.00.060; версия отображается в dashboard и editor.

Реализовано: локальная регистрация/вход, проекты с проверкой владельца, несколько страниц, десять структурных секций, глобальная тема проекта (восемь цветов, типографика и скругление) с сохранением в валидируемых настройках проекта и синхронизацией с Project Data, слои и инспектор стилей/свойств, Flex/Grid, desktop/tablet/mobile canvas, Undo/Redo, sandbox preview, debounce-автосохранение, история до 200 ревизий с безопасным восстановлением, защита от конфликта версий, JSON export и статический ZIP export.

AI foundation: серверный OpenRouter adapter, constrained design-plan endpoint и полноценная генерация HTML/CSS с предпросмотром и отдельным подтверждением импорта. Отдельный authenticated `POST /api/projects/{id}/operations` принимает ограниченный список typed operations (`create`, `update_content`, `update_styles`, `update_layout`, `delete`, `move`, `reorder`) и сохраняет каждое успешное применение новой CAS-ревизией. Удаление требует `confirm: true`; создание назначает стабильные component IDs. API-ключ, основная и резервная модели OpenRouter настраиваются в «Настройки сайта → AI Engine» конкретного проекта; ключ хранится сервером в зашифрованном виде и не входит в Project Data. Полный live-тест генерации, применения, сохранения/reload и публикации остаётся отдельным acceptance gate; синтетические и fixture-проверки не тарифицируют провайдера. Также не реализованы targeted AI edits, MCP, Zero Canvas, custom domains и templates marketplace.

## Локальный запуск

PHP 8.2+ (PDO SQLite, DOM/libxml, mbstring, Zip, cURL для AI), Node 22.12+ для сборки. Проверено на PHP 8.5.8 и Node 24.15.0.

```sh
npm ci
npm run build
npm run serve
```

После `npm run serve` приложение открывается по уникальному локальному адресу [http://juzimder-ai.localhost:8080](http://juzimder-ai.localhost:8080). Команда проверяет этот адрес: если Juzimder уже работает, повторный запуск сообщит URL и завершится без ошибки занятого порта; старые адреса `127.0.0.1:8080` и `localhost:8080` перенаправляются на него. Для локальной разработки команда включает loopback-only вход `admin/admin`; при первом входе создаётся отдельный тестовый аккаунт. Сервер остаётся привязан только к этому компьютеру; не включать dev login на публичном сервере. Локальные сессии изолируются по пути SQLite-базы, а после переключения базы устаревшая сессия сбрасывается с предложением войти снова. Данные — `var/app.sqlite` вне web root. API-ключ AI вводится только в «Настройки сайта → AI Engine» и не задаётся через переменные окружения. Локальный опубликованный сайт использует host вида `<project-id>.juzimder-ai.localhost:8080`; production требует wildcard DNS/TLS и конфигурации `JUZIMDER_PUBLIC_HOST_SUFFIX`. `JUZIMDER_DB` можно использовать для отдельной локальной базы; `.env.example` документирует только серверный путь к базе, dotenv не подключён. Для hot reload: параллельно `npm run dev`.

```sh
npm test
```

Стек: GrapesJS 0.23.8, Vite 8.3.4, browser JS/CSS, native PHP/PDO SQLite. Node не требуется на PHP hosting после сборки. Backend и SQLite расположены вне public. Текущая версия предназначена для локальной работы; перед публичным размещением пройти [security checklist](docs/SECURITY.md) и [deployment guide](docs/DEPLOYMENT.md).

## Автоматическая замена OpenRouter-профилей · 00.00.039

Все четыре AI-операции используют request-scoped цепочку сохранённых профилей: сначала активный, затем остальные в порядке создания. Каждый профиль использует собственный зашифрованный ключ и модель; его необязательная резервная модель сохраняет прежнюю роль. При сетевом таймауте, HTTP 408/429/5xx и отказе доступа 401/403 выполняется переход к следующему профилю. Некорректный запрос или ответ, ошибка HTML/CSS/Skill validation не запускают перебор ключей. При нескольких профилях нет повторного сетевого запроса к одной модели до перехода к следующему профилю. Общий бюджет 100 секунд делится между оставшимися профилями; максимум одной передачи повышен до 60 секунд. Активный выбор в БД не меняется. Успешный профиль становится первым для исправляющей попытки в рамках того же запроса; его название доступно в metadata и preview. UI предупреждает о переключении и возможной стоимости каждой попытки. Секреты не возвращаются клиенту.

Тесты PASS: owner protection, active-first ключи из vault, сохранение active selection, failover после timeout/429/502/401, отдельный ключ каждого профиля, повторное использование успешного профиля, отсутствие переключения при HTTP400, ограниченный перебор при недоступности всех, сохранение общего времени. npm test, build, PHP syntax и diff checks прошли; Vite сохраняет предупреждение большого GrapesJS chunk.

Live: настройки показывают версию 00.00.039 и описание автоматической замены; активный профиль «Резервный» и ревизия проекта 38 сохранены. Генерация с pottery Skill и двумя существующими профилями закончилась контролируемой временной недоступностью, без нового содержимого страницы. Успешный реальный failover → дизайн → визуальная приёмка → save/reload остаётся NOT RUN из-за недоступности провайдера; успешное переключение доказано fixtures, а не реальным ответом OpenRouter.

## Диагностика длительного ответа и профиль принятого результата · 00.00.041

Транспорт фиксирует только числовые диагностические поля при сбое: curl code, HTTP status, elapsedMs, firstByteMs и receivedBytes. Ключи, headers, prompts и response body не логируются. CURL timeout 28 теперь имеет отдельную категорию timeout и понятную подсказку; он остаётся retryable для автоматической замены профилей. Ошибки соединения и отказ ключа не смешиваются с таймаутом ответа. Исправлен metadata bug: если исправляющую генерацию выполнил другой профиль, accepted result показывает его название, а не название первой неудачной попытки.

Первый профиль: HTTP200, первый байт 772 мс, timeout49001 мс, 187 байт; второй: HTTP200, первый байт5811 мс, timeout50001 мс, 187 байт. Уменьшение бюджета само по себе не решило проблему. Принудительное снятие timeout или ослабление sanitizer не выполнялись.

## Фоновая генерация и первая сквозная Skill-приёмка · 00.00.042

Редактор запускает POST generation-jobs с pageId и текущей версией; ответ 202 возвращается до обращения к модели. Отдельный доверенный PHP CLI worker получает только DB path и job ID, атомарно забирает queued задачу, читает ключи из vault и выполняет прежний sanitizer/Skill audit. В приватной SQLite сохраняются request snapshot (описание и выбранный Skill), состояния queued/running/succeeded/failed и проверенный результат. Ни ключей, ни cookies в payload нет. Project Data не изменяется worker-ом. Применение — явный preview/confirmation и прежний CAS save. Одновременно разрешена одна активная задача на проект; повторный worker не повторяет вызов провайдера. GET статуса защищён owner; POST — auth/CSRF/validation/version/rate limit. Клиент опрашивает статус короткими запросами и восстанавливает последнюю задачу страницы после reload. Закрытие окна не отменяет provider call, о чём сообщается до запуска.

## Отмена фоновой генерации · 00.00.043

Во время ожидания доступна «Отменить генерацию». POST cancel защищён owner/CSRF и не принимает дополнительные данные. Queued задача сразу становится cancelled и не может быть захвачена worker-ом. Running задача переходит в cancelling: слот проекта остаётся занят до подтверждения worker, чтобы новая генерация не создавала параллельный расход. Worker проверяет флаг через cURL progress callback (DB check не чаще двух раз в секунду), прерывает текущий transfer и завершает cancelled. Отмена не запускает retry/fallback; пришедший одновременно результат отбрасывается, если cancellation успела первой. Завершённую succeeded/failed задачу отменить нельзя (409). SQL migration10 сохраняет предыдущие jobs и расширяет CHECK/unique active index. При аварии worker прежний watchdog освобождает зависшую задачу.

Отмена локально прерывает запрос; провайдер может учесть уже потраченные токены и не гарантирует остановку своей внутренней обработки. Это прямо сообщается в UI. Отменённая задача восстанавливается после reload с сообщением об отмене, без preview/apply. Проект не меняется.

Live PASS: на изолированной QA-странице запущена реальная синтетическая Cancellation QA задача, нажата отмена, worker подтвердил cancelled, кнопка нового запуска снова доступна. После reload и восстановления сохранились описание и отменённый статус; apply отсутствует. Сохранённая страница осталась revision39. Снимок: /tmp/juzimder-cancellation-043.png.
